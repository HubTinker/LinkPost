# Архитектура: Layered Architecture

## Обзор

LinkPost использует Layered Architecture — простую горизонтальную архитектуру с разделением на слои (маршруты, контроллеры/обработчики, бизнес-логика, доступ к данным). Выбрана из-за небольшого размера проекта, низкой предметной сложности и единственного разработчика. Каждый слой отвечает только за свою зону ответственности и зависит только от нижележащего слоя.

## Обоснование решения

- **Тип проекта:** Telegram-подобный бот с управлением ключами и ссылками
- **Технологический стек:** JavaScript, Hono, Vercel KV
- **Ключевой фактор:** CRUD-приложение с одним разработчиком — избыточность строгих паттернов не оправдана

## Структура папок

```
lib/
├── max-api.js       # Слой интеграции (MAX Bot API — HTTP-клиент)
└── storage.js       # Слой доступа к данным (Vercel KV)

api/
└── index.js         # Слой представления (Hono-роуты + обработчики)
```

## Правила зависимостей

- **Строгое направление вниз:** Зависимости направлены сверху вниз:
  `Маршруты → Обработчики → Бизнес-логика → Хранилище → Внешние API`
- ✅ Маршруты вызывают функции-обработчики
- ✅ Обработчики используют функции хранилища и API
- ❌ Модуль хранилища не может импортировать маршруты
- ❌ Модуль API не может импортировать модуль маршрутов

## Коммуникация между слоями

- Обработчики вызывают функции нижележащих слоёв напрямую (прямые вызовы функций, без DI)
- Синхронное выполнение на Edge (fetch + await)
- Данные передаются как простые объекты и примитивы

## Ключевые принципы

1. **Тонкие обработчики:** Обработчики проверяют входные данные и вызывают сервисные функции. Бизнес-логика не должна быть в обработчике.
2. **Каждый слой имеет одну ответственность:** API-слой — HTTP-запросы к MAX; Хранилище — работа с KV; Обработчики — логика команд.
3. **Простота:** Никакого DI-контейнера, DI через импорты и аргументы функций.

### Хранилище не зависит от обработчиков

```javascript
// lib/storage.js — слой данных
import { kv } from '@vercel/kv';

export async function setLink(key, url, message) {
  await kv.set(`link:${key}`, { url, message });
}

// api/index.js — использует хранилище, но не наоборот
import { setLink } from '../lib/storage.js';
```

## Анти-паттерны

- ❌ **Толстые обработчики:** Вся логика в одной функции/маршруте. Выносите бизнес-логику в отдельные функции.
- ❌ **Перепрыгивание слоёв:** Обработчик, работающий с MAX API напрямую, минуя слой API-обёртки.
- ❌ **Циркулярные зависимости:** Файл A импортирует B, B импортирует A. Используйте общие модули.
