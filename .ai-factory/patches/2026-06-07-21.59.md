# MAX API message format: recipient/body → chat_id query param

**Date:** 2026-06-07 21:59
**Files:** lib/max-api.js, poll.js
**Severity:** high

## Problem

Bot returned `400 Unknown recipient` when trying to reply to messages
via Long Polling. Additionally, poller hit `429 Too Many Requests`
after rapid retries on error.

## Root Cause

MAX Bot API `POST /messages` expects `chat_id` as a **query parameter**
(e.g. `/messages?chat_id=123`), with `text`/`attachments`/`format` as
**body fields**. The code was sending `recipient: { chat_id }` and
`body: { type: 'text', text }` inside the body — a format from a
different API (Telegram-like) that MAX does not support.

## Solution

1. **lib/max-api.js**: Removed the `recipient` wrapper and `body`
   nesting. Now passes `chat_id` via query string and `text` directly
   in the body. Same for `sendMessageWithLink`.
2. **poll.js**: Added 429 rate-limit handling with exponential backoff
   (1s → 30s max), `types` filter to reduce noise, and try/catch for
   network errors.

## Prevention

- Always consult the target API's actual REST docs before assuming
  request format (Telegram vs MAX differ significantly)
- `POST /messages` signature: query params = recipient selector
  (`chat_id`/`user_id`), body = message payload (`text`, `attachments`)
- Add rate-limit handling to polling loops by default
