# KEYS → SMEMBERS, input validation, privacy logs, and test isolation

**Date:** 2026-06-07 22:50
**Files:** lib/storage.js, lib/kv-mock.js, lib/max-api.js, api/index.js, test/handler.test.js
**Severity:** low

## Problem

Code review of LinkPost bot found 6 non-blocking issues:

1. `getAllLinks()` used `KV.keys('link:*')` — O(N) blocking scan on Redis, not scalable
2. `console.log` in `request()` logged full request body including user message text — privacy concern on Vercel
3. No input validation for key length, URL length, or message length in `/setlink`
4. `markAsRead().catch(() => {})` silently swallowed errors — no debugging visibility
5. `const fetchCalls = []` was global with `fetchCalls.length = 0` reset — if a test failed before `beforeEach`, next test would get stale data
6. Code review finding #1 ("chat_id should be in body") was incorrect — previous patches proved MAX API requires chat_id as query parameter

## Root Cause

- `getAllLinks()` was implemented before `links_all` set pattern existed (the `users_all` set pattern was already in use in the same file but not applied to links)
- Request body was logged for debugging and never trimmed for production
- Input validation was minimal — only URL format was checked, no length limits
- `markAsRead` is fire-and-forget by design, but errors should still surface in logs
- Test isolation used `fetchCalls.length = 0` (mutating array in place) instead of full reassignment — fragile pattern
- Code review incorrectly assumed MAX API uses Telegram-style body format; existing patches from the same project contradicted this

## Solution

1. **storage.js**: Added `LINKS_SET` constant. `setLink()` now calls `sadd(LINKS_SET, key)`, `delLink()` calls `srem(LINKS_SET, key)`. `getAllLinks()` reads keys via `smembers(LINKS_SET)` instead of `keys(link:*)`. This matches the existing `users_all` pattern.
2. **kv-mock.js**: Added `srem()` implementation to support the new operation.
3. **max-api.js**: Removed `JSON.stringify(body)` from request log — now logs only `method` and `path`.
4. **api/index.js**: Added key length check (max 50), URL length check (max 2048), message truncation (slice 0-4096). Changed `markAsRead().catch(() => {})` to log errors via `console.warn`.
5. **test/handler.test.js**: Changed `const fetchCalls = []` to `let fetchCalls` with fallback safety in the mock fetch function. All `beforeEach` use `fetchCalls = []` (reassignment) instead of `fetchCalls.length = 0` (mutation).
6. **test/handler.test.js**: Added 2 new tests — key length validation (>50 chars) and URL length validation (>2048 chars). Updated `/links should list all links` test to populate `links_all` set via `kv.sadd`.

## Prevention

- When adding KV operations that enumerate items, ALWAYS use a dedicated Set instead of `KEYS` pattern — `KEYS` is O(N) and blocks Redis
- Log metadata, not data — never include user-generated content in production logs without explicit consideration
- Add input validation for EVERY user-supplied parameter that enters the system, not just format checks
- Fire-and-forget patterns should still log errors for debugging — use `.catch(e => console.warn(...))` as default
- Use `let` with reassignment in `beforeEach` for shared test state — mutating arrays in place via `.length = 0` is fragile
- Before accepting code review findings, cross-check against project patches — existing fixes may contradict assumptions
