# API Reference

## Webhook

**POST** `/webhook`

Основной эндпоинт для приёма событий от MAX.

### Формат запроса

```json
{
  "update_type": "bot_started",
  "chat_id": 1234567890,
  "user": {
    "user_id": 1234567890,
    "name": "Иван",
    "username": "ivan_petrov"
  },
  "payload": "vip"
}
```

### Обрабатываемые события

| `update_type` | Описание |
|---------------|----------|
| `bot_started` | Пользователь запустил бота (включая deep-ссылки с `?start=`) |
| `message_created` | Новое сообщение |
| `message_callback` | Нажатие на inline-кнопку |

### Ответ

Всегда `200 OK`, даже при ошибке в обработчике:

```json
{ "ok": true }
```

### Команды бота

| Команда | Доступ | Описание |
|---------|--------|----------|
| `/start` | Все | Приветственное сообщение |
| `/setlink <key> <url> <msg>` | Админ | Создать связку (сохраняет `creator_id`) |
| `/dellink <key>` | Админ | Запрос на удаление связки (с подтверждением). Команда доступна только админам |
| `/links [N]` | Все | Постраничный список связок (20 шт): админ — все, создатель — только свои. `N` — номер страницы |
| `/link <key>` | Все | Карточка связки: текст сообщения, ссылка, диплинк; кнопки «Удалить», «Посмотреть». Создатель — только свои |
| `/users` | Админ | Количество пользователей |
| `<ключ>` | Все | Получить ссылку по ключу |

Каждая связка (`link:<key>`) хранит поле `creator_id` — ID пользователя, создавшего ключ. Для связок, созданных до введения этого поля, миграция назначает первого админа из `ADMIN_IDS`.

### Inline-кнопки (callback-колбэки)

| Колбэк | Где появляется | Описание |
|--------|----------------|----------|
| `del:<key>` | Кнопка `🗑 Удалить` в карточке | Показывает диалог подтверждения удаления |
| `confirm_del:<key>` | Кнопка `✅ Да, удалить` в диалоге | Удаляет связку; после — «🔙 К списку» |
| `links_page:<n>` | Кнопки `⬅️` / `➡️` в списке | Переход на страницу списка |
| `link_preview:<key>` | Кнопка `👁 Посмотреть` в карточке | Отправляет сообщение связки как видит пользователь |
| `edit_msg:<key>` | Кнопка `✏️` в карточке | Режим редактирования текста связки: запрашивает новый текст (лимит 4096), ставит KV-флаг `pending_edit:<userId>` |
| `edit_cancel:<key>` | Кнопка `❌ Отмена` на экране приглашения | Снимает режим и возвращает карточку на месте |
| `back` | Кнопка `🔙 Назад` (только админ) | Возвращает в главное меню админа; не-админ получает подсказку |
| `links` | Кнопка `❌ Нет` в диалоге удаления (карточка), «🔙 К списку», «🔙 Назад» в карточке | Возвращает к списку связок |
| `create` | Кнопка `➕ Создать` в главном меню | Показывает подсказку `/setlink` |
| `users` | Кнопка `👥 Пользователи` | Показывает количество пользователей |
| `broadcast_menu` | Кнопка `📨 Рассылка` | Меню рассылок: новая, список, очистка неактивных |

### Навигация

Раздел «Связки»: главное меню → список (постранично, кнопки `⬅️`/`➡️`, «Назад» только у админа) → карточка через `/link <key>` или ввод команды. Карточка: текст сообщения, ссылка, диплинк, кнопки «✏️», «🗑 Удалить», «👁 Посмотреть», «🔙 Назад» (к списку). У создателей (не-админов) список и карточки — только для своих связок.

Режим редактирования текста: кнопка «✏️» → бот ждёт новый текст (KV-флаг `pending_edit:<userId>`, TTL 15 мин). Сообщение без текста — бот просит прислать текст; любая команда `/…` или чужая кнопка снимают режим («⚠️ Режим редактирования сброшен.»); текст, начинающийся с `/`, через режим не записать — используйте `/setlink`. Права (`canManage`) и существование ключа проверяются и при нажатии, и при сохранении. Успех — карточка с «✅ Текст обновлён!»; `url`, `creator_id`, `created_at`, статистика и подписчики не меняются.

### Обработка событий

В дополнение к `message_created`, бот обрабатывает `message_callback` для inline-кнопок и `bot_started` для глубоких ссылок. На каждую callback-кнопку бот отвечает `POST /answers?callback_id=…` (лимит MAX — не более 2 ответов в секунду на диалог; ошибка ack не блокирует обработку).

## Setup Webhook

**GET** `/setup-webhook?secret=ВАШ_SECRET`

Регистрирует webhook в MAX API. Вызвать один раз после деплоя.

### Параметры

| Параметр | Описание |
|----------|----------|
| `secret` | Секретный ключ из `SETUP_SECRET` |

### Ответ

```json
{
  "webhookUrl": "https://.../webhook",
  "result": { "success": true }
}
```

## Коды ответов

| Код | Значение |
|-----|----------|
| 200 | Успех |
| 400 | Неверный JSON |
| 403 | Неверный secret |

## Рассылки (broadcast)

Поток: черновик (текст → картинки → кнопки) → экран «Кому отправляем?» (лимит 100/200/500/1000, «Свой вариант», «Всем») → запуск. Дубликатов нет: повторный запуск той же рассылки («📤 Разослать ещё») доставляется только тем, кто её ещё не получал.

**GET** `/process-broadcasts?secret=…` — продолжение цепочки рассылки (батчами по 20, вызывается самим ботом). **GET** `/cron-process-broadcasts` — cron-подхват (Vercel cron или локальный вызов).

Если рассылка зависла в статусе «Отправляется» (например, при сбое деплоя) — восстановите: «⏸ Остановить» → «▶️ Возобновить».
