### Файлы

- Изменить: `api/index.js`

### Шаги

1. **Экран «Кому отправляем?»** (§5.1): открытие из предпросмотра («✅ Отправить»), «▶️ Запустить» у черновика, «📤 Разослать ещё» у `sent`/`cancelled`; текст с X/M/K; кнопки `[100] [200] [500] [1000] [Свой вариант] [Всем] [🔙]`; при `M = 0` — без числовых кнопок, старт невозможен, текст «📭 Нет новых получателей — все уже получили эту рассылку.»
2. **«Свой вариант»** (§5.2): `_awaiting_limit = true` (у остальных рассылок админа флаг снимается), ответ «Введите число получателей (1–10000).»; перехват в `handleMessage` **до** ветки черновика: `getAllBroadcasts().find(b => b._awaiting_limit && b.created_by === userId)` (регрессия блокера: «Разослать ещё» на `sent`/`cancelled`); валидное целое 1–10000 → запуск, невалидное → «Введите число от 1 до 10000», флаг остаётся; снятие флага при старте, «🔙 Назад», открытии другого `broadcast_view`/экрана получателей.
3. **Старт запуска** (§5.3): проверка статуса (`draft`/`sent`/`cancelled`; иначе «Сначала остановите текущую отправку.»); `updateBroadcast` c `status='scheduled'`, `scheduled_at=Date.now()`, `created_by_chat_id=chatId`, `limit = n | null`, `_awaiting_limit=false`, `_run_sent_at_start = scard(:sent)`; `clearRunAttempted(bid)` — единственная точка сброса; первый батч инлайн через `runBroadcastBatch`, затем цепочка `/process-broadcasts`.
4. **Кнопки деталей** (§5.4): таблица по статусам; «▶️ Возобновить» (`cancelled`) = тот же запуск (без запроса числа, `run_attempted` не трогаем); «📤 Разослать ещё» (`sent`/`cancelled`) = новый запуск через экран получателей; «🔄 Перезапустить» удаляется.
5. **Прогресс/детали/статистика** (§5.5): in-flight `📤 Запуск: S / L` (при «Всем» — «S из M»), «❌ Ошибок за запуск: …»; итог `✅ Получили: N всего (в этот запуск S) · ❌ Ошибок: … · 🚫 Пропущено неактивных: …`; `broadcast_stats`: `в этом запуске: S, лимит: L | <все>`; прогресс каждые 15 доставок с S/L.
6. **Обновить существующие тесты** (§7.4): `broadcast_restart` → кнопки нет, семантика «Разослать ещё»; тесты прогресса/статуса → новые тексты.
7. TDD: красный → реализация → зелёный → `npm test`.

### Тест-кейсы (§7.3)

- Предпросмотр → экран получателей.
- Пресет-старт и цепочка; «Всем».
- «Свой вариант»: валид → старт; невалид → повторный запрос; «🔙 Назад» снимает флаг.
- Регрессия блокера: `sent`/`cancelled` → «Разослать ещё» → «Свой вариант» → ввод числа → запуск стартовал.
- Повтор на `sent`: память сохраняется, повторных доставок нет.
- `cancelled`: «Возобновить» — без дублей и без запроса числа; «Разослать ещё» — новый запуск.
- `M = 0`: старт невозможен.
- Запрет старта при `scheduled`/`sending`.
- Прогресс/детали/статистика с S/L.
