# Спецификация: Редизайн раздела «Связки»

**Дата:** 2026-08-12
**Статус:** Согласовано (brainstorming session + code-review)
**Файлы:** `api/index.js`, `test/handler.test.js`, README/docs

---

## 1. Цель

Переделать раздел «Связки» бота в навигацию «список → карточка связки». Добавить возможность предпросмотра сообщения связки так, как его видят пользователи. Разрешить создателям связок (не-админам) просматривать и управлять своими связками.

---

## 2. Навигация

```
Главное меню → «📋 Связки» (или /links)
        ↓
Список связок (постранично, 20 шт)
        ↓ (ввести /link <ключ>)
Карточка связки: ключ, текст, ссылка, диплинк
        ├─ [🗑 Удалить] → подтверждение → удалена
        ├─ [👁 Посмотреть] → бот шлёт сообщение как видит пользователь
        └─ [🔙 Назад] → снова список
```

---

## 3. Список связок (пагинация)

### 3.1. Формат
- Строка: `N. 🔑 <ключ> — /link <ключ>` (нумерация сквозная: стр. 2 начинается с 21)
- Заголовок сообщения: `📋 Связки (N, стр. P из M)` (админ) / `📋 Ваши связки (N, стр. P из M)` (создатель)
- Номер страницы выводится **в тексте сообщения**, не в кнопке

### 3.2. Команды
- `/links` — страница 1
- `/links <N>` — страница N; зажимается в диапазон `[1..max]`
- Нечисловое значение (`/links abc`) → страница 1

### 3.3. Кнопки под сообщением
- Навигационные кнопки — только `[⬅️] [➡️]` (payload `links_page:<n>`), админу дополнительно `[🔙 Назад]` (`back`)
- **На границах кнопка скрывается**: стр. 1 → только `[➡️]`, последняя страница → только `[⬅️]` (у MAX нет disabled-кнопок; бессмысленная кнопка раздражает)
- `links_page:<n>` из callback тоже зажимается в диапазон `[1..max]` — payload'у не доверяем

### 3.4. Пустой список
- Админ: `📭 Нет активных связок. Добавьте первую через /setlink.` + кнопка `[🔙 Назад]` (`back`)
- Создатель: `📭 У вас пока нет связок.` — без кнопок и без совета `/setlink`: команда `/setlink` не-админам недоступна (фильтр slash-команд), кнопка «Создать» вела бы на невыполнимую команду. Отправка — `sendMessage` без клавиатуры

### 3.5. Сортировка
- Связки сортируются по ключу (`localeCompare`) в `showLinksList` для стабильной пагинации (порядок `smembers` не гарантирован). Storage-слой не трогаем

## 4. Карточка связки (`/link <ключ>`)

### 4.1. Команда
```
/link <ключ>
```

### 4.2. Usage (ключ не указан)
```
⚠️ Формат: /link <ключ>
Пример: /link vip
```

### 4.3. Содержимое карточки
```
🔑 Ключ: vip

💬 Сообщение:
<текст связки; обрезан до 3000 символов, при обрезке + «...»; если message пустой — «(нет текста)»>

🔗 Ссылка: https://max.ru/channel/xxx

🔗 Диплинк: https://max.ru/<бот>?start=vip
```
- URL показываем полностью — он нужен для копирования (при `/setlink` URL ограничен 2048; случай, когда оба лимита одновременно, редок)

### 4.4. Кнопки (два ряда — на мобильном три в ряд мелкие)
```
[🗑 Удалить] [👁 Посмотреть]
[🔙 Назад]
```
- `del:<key>` — подтверждение удаления
- `link_preview:<key>` — предпросмотр
- `links` — вернуться к списку (стр. 1)

### 4.5. Ошибки
- **Не-админ** — единое сообщение на оба случая (не раскрываем существование чужой связки):
  `⛔ Ключ "<ключ>" не найден или у вас нет прав.`
- **Админ**:
  - Ключ не найден: `❌ Ключ "<ключ>" не найден.`
  - Нет прав: `⛔ Вы можете открывать только свои ключи.` (страховка — для админа неприменимо)
- Единое сообщение для не-админа действует во всех проверках по ключу: `/link`, `del:`, `confirm_del:`, `link_preview:`

---

## 5. Кнопки карточки

### 5.1. 👁 Посмотреть (`link_preview:<key>`)
- Отправляет сообщение **ровно как видит пользователь** (тот же вызов, что в `handleBotStarted` при диплинке):
  ```js
  sendMessageWithLink(chatId, link.message, { label: LINK_BUTTON_LABEL, url: link.url })
  ```
  где `const LINK_BUTTON_LABEL = '👉 Перейти в канал'`
- **Без** регистрации подписчика: `saveUser` / `addUserToLink` **не вызываются** — админ не должен попасть в статистику как подписчик
- Карточка остаётся в чате (без повторного рендера)
- Проверка прав: `canManage(userId, link)` — не-админ не может превьюить чужую связку
- Не найдена / нет прав → те же сообщения, что в 4.5

### 5.2. 🗑 Удалить (`del:<key>`)
- Существующий флоу подтверждения:
  ```
  🗑 Удалить связку "<ключ>"?
  [✅ Да, удалить] [❌ Нет]
  ```
- `❌ Нет` → `links` (возврат к списку)
- `✅ Да, удалить` (`confirm_del:<key>`) → удаление → сообщение:
  ```
  ✅ Связка "<ключ>" удалена.
  [🔙 К списку]
  ```
  Кнопка: `{ type: 'callback', text: '🔙 К списку', data: 'links' }` — ведёт на `links`, а не `back` (пользователь работал со списком, возвращаем его в список; для всех: и админов, и создателей). Текст именно «К списку», а не «Назад» — «Назад» ассоциируется с меню
- **Порядок проверок в `del:` / `confirm_del:`**: сначала `canManage`, только после — формирование текста подтверждения. Тексты отказа не содержат чужих `url`/`message`

### 5.3. 🔙 Назад (`links`)
- Повторный рендер списка связок (стр. 1) — работает и для создателей (рендерит их собственные связки)

## 6. Права доступа

### 6.1. Хелпер
```js
function canManage (userId, link) {
  return isAdmin(userId) || link.creator_id === userId
}
```
- Применяется в: `/link`, `/dellink` (унификация — поведение там уже корректно), `del:`, `confirm_del:`, `link_preview:`
- `creator_id === null` (старые связки): только админ может управлять — документированное поведение (миграция — отдельная задача)
- **Унификация ошибок только для не-админов** (см. 4.5): «не найден» и «нет прав» не различаются — перебором ключей нельзя выяснить существование чужих связок. Админу сообщения можно различать
- **Проверка прав выполняется до формирования любого текста с данными связки** (`url`/`message`) — тексты отказа не содержат данных чужой связки

### 6.2. Фильтр slash-команд (`handleMessage`, стр. ~224)
```js
const isAllowedLinkCmd = text === '/links' || text.startsWith('/links ') ||
                         text === '/link' || text.startsWith('/link ')
if (!isAdmin(userId) && text.startsWith('/') && !isAllowedLinkCmd) return
```
- Не-админам разрешены только `/links` и `/link` (в т.ч. голый `/link` — покажет usage)
- Остальные slash-команды молча игнорируются
- **В обработчиках — только точные матчи** (важно: `startsWith('/link')` поймал бы `/links`):
  ```js
  if (text === '/links' || text.startsWith('/links ')) { ... }   // проверять раньше
  if (text === '/link' || text.startsWith('/link ')) { ... }
  ```

### 6.3. Фильтр callback'ов (`handleCallbackQuery`, стр. ~430)
- Явный guard на входе — не-админ отсекается, кроме whitelist:
  ```js
  const ALLOWED_NON_ADMIN_PAYLOADS = ['links', 'back']
  const ALLOWED_NON_ADMIN_PREFIXES = ['links_page:', 'link_preview:', 'del:', 'confirm_del:']
  const isAllowed = ALLOWED_NON_ADMIN_PAYLOADS.includes(cb.payload) ||
    ALLOWED_NON_ADMIN_PREFIXES.some(p => cb.payload.startsWith(p))
  if (!isAdmin(userId) && !isAllowed) return
  ```
- `back` в whitelist — чтобы дойти до guard-хендлера и получить подсказку (см. ниже), а не молчаливый отказ
- Внутри каждого разрешённого payload'а — проверка `canManage` (для `links_page:*` список рендерится только из своих связок, проверка на уровне данных)
- `back`: guard для не-админа:
  ```js
  if (cb.payload === 'back') {
    if (!isAdmin(userId)) return sendMessage(chatId, 'Используйте /links для просмотра ваших связок.')
    return showAdminMenu(chatId, userId)
  }
  ```
  (защита от старых сообщений; в новых UI кнопка `back` не-админам не показывается — у создателя в списке только `[⬅️] [➡️]`, на единственной странице клавиатура отсутствует)

## 7. Техническая реализация

### 7.1. Новые функции (в `api/index.js`)
- `showLinksList(chatId, userId, page = 1)` — единая точка рендера списка: загрузка (все/свои), сортировка, слайс страницы, сборка текста и кнопок
- `showLinkCard(chatId, userId, key)` — рендер карточки (обрезка message до 3000, кнопки)
- `canManage(userId, link)` — проверка прав

### 7.2. Изменения
- `const LINK_BUTTON_LABEL = '👉 Перейти в канал'` — используется в `handleBotStarted` (замена хардкода) и `link_preview`
- `buildLinksKeyboard` — заменить на строитель кнопок пагинации (или включить логику в `showLinksList`)
- callback `links` → `showLinksList(chatId, userId, 1)`
- handler `/links` — парсит страницу (нечисловое → 1), вызывает `showLinksList`
- handler `/link` — новый: usage, `showLinkCard`
- `handleCallbackQuery`:
  - новый `link_preview:<key>` (проверка `canManage`)
  - новый `links_page:<n>` (кламп диапазона, свои связки для не-админов)
  - ослабить фильтр на разрешённые payload'ы (6.3)
  - guard `back` для не-админов
- `del:` / `confirm_del:` — проверка `creator_id !== userId` → `!canManage(userId, existing)`, выполняется **до** формирования текста подтверждения
- `confirm_del:` — финальная кнопка `back` → `{ text: '🔙 К списку', data: 'links' }`
- `showAdminMenu(chatId, userId)` — guard в начале: `if (!isAdmin(userId)) return` (defense-in-depth: вызовы уже защищены, но функция не должна доверять caller'у)

### 7.3. Что не трогаем
- Раздел «Статистика → По ключу» (`stats_key:<key>`) — остаётся как есть (бонус: удаление оттуда тоже чинится через `canManage`)
- Рассылки — без изменений
- `handleBotStarted` — логика без изменений (только замена хардкод-строки на `LINK_BUTTON_LABEL`)
- `lib/storage.js` — без изменений

## 8. Известные ограничения

- Сообщение связки отправляется без `format` (plain text). Markdown в связках не поддерживается — консистентно с текущим поведением диплинка. Если потребуется — отдельная задача
- `link_preview` отправляет ровно то, что отправляет диплинк-флоу, включая edge case пустой `message` у legacy-связок (поведение совпадает, не «чиним» отдельно; в карточке при этом показывается «(нет текста)»)
- Пагинация в памяти (`getAllLinks()` / `getLinksByCreator()` — `smembers` + N get-ов). При сотнях связок приемлемо для KV; при тысячах — отдельная задача

- Старые связки (`creator_id: null`) — недоступны не-админам
